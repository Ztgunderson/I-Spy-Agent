    1Question and setup

    Scalable oversight asks whether a weaker overseer can catch a stronger agent. We test the cheapest overseer available: a decision model that reads only an agent's output and returns P(covert) in one forward pass. The monitors run from 0.6B to 27B parameters, quantised to fit an edge device, and none sees model internals.

    System One models, not an LLM judge

    The usual black-box monitor is an LLM-as-judge: a chat model reads the transcript, writes a verdict, and a score is parsed from the text. Our monitors are System One models [6]: decision models that "return typed answers with probabilities instead of text". Each one picks from the answers we list, here yes or no to a fixed question, in one forward pass. It writes nothing, so there is no verdict to parse, the score is a probability that a threshold can be set on directly, and the cost is the input alone. NARCBench reports that transcript judges did poorly unless given threat details and examples [2]. We ask whether a small decision model, with one pre-registered question and no examples, does better, and at what cost.

    The two benchmarks test different threats. LinuxArena is single-agent sabotage: an agent hides functionality in a file it writes. NARCBench-Stego is multi-agent collusion: at a blackjack table, one agent (the counter) covertly signals the card count to a partner (the big player) through ordinary-looking table talk, and the partner bets on it. Detecting the counter from public messages is detecting collusion through a steganographic channel.

    Questions: (a) how well do these monitors detect covert behaviour on each surface, (b) does a larger monitor or fine-tuning help, (c) how do they fail, and (d) are they useful as an oversight layer at an alarm rate an operator could accept.

    5Operating point

    AUROC hides what an operator needs: how many attacks are caught at a tolerable alarm rate. Recall here is computed from per-item scores, with the threshold set on honest items.

    Using the FPR dial. Drag it to set the alarm budget, the share of honest items (honest files, players who are not the counter) that a monitor may flag. Each monitor's threshold is set so that this share of its honest scores sits above it, separately for each benchmark and writer. The figures then show how many attacks score above the same line. Moving the dial right catches more attacks and raises more false alarms. The readout gives the number of honest items behind the percentage. Ties at the threshold are not flagged.

    7Correlated failure

    8Does a monitor catch its own backbone's collusion?

    Most monitors here are fine-tunes of Qwen3.5 or Qwen3.8. If a monitor shared some of a colluder's habits, it might read that colluder's covert talk better. That would make same-family oversight easier, or put it at risk if the monitor learned to overlook the colluder instead. We played NARCBench-Stego with five Qwen writers and scored every player with every monitor: 7 writers × 15 monitors, 13 cells where the monitor and the writer share base weights.

    Does the covert channel work?

    A writer's collusion is real only if the partner acts on the signal. For each collusion shoe we correlate the big player's bets with the true count, and compare against honest players at the same table.
